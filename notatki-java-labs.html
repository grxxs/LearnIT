1.1 · SecretData.java – klasa generyczna 
package org.example;

Pakiet org.example.

public class SecretData <T1, T2>{

<T1, T2> – dwa parametry typu. Klasa nie wie, czym będą pola, dopóki ktoś nie utworzy obiektu, np. SecretData<String, PrintStream> albo SecretData<Integer, Double>. Kompilator pilnuje typów (bez rzutowań).

    private T1 data1;
    private T2 data2;

Dwa pola prywatne typów T1 i T2 – dostęp tylko przez gettery/settery (enkapsulacja).

    public SecretData(T1 data1, T2 data2){
        this.data1 = data1;
        this.data2 = data2;
    }

Konstruktor ustawia oba pola. Nie ma konstruktora bezargumentowego – dlatego podklasa musi wywołać super(data1, data2).

    public void setData1(T1 data1) {this.data1 = data1;}
    public void setData2(T2 data2) {this.data2 = data2;}

    public T1 getData1() {return data1;}
    public T2 getData2() {return data2;}

}

Settery (setData1, setData2) przyjmują wartość typu T1/T2 i zmieniają pole. Gettery zwracają T1/T2, więc getData1() dla SecretData<String,…> zwraca od razu String.

1.1 · SecretDataWithPrintOnScreen.java – dziedziczenie + interfejs

1.1 · SecretDataActions.java – metody generyczne z ograniczeniami 
package org.example;

import java.io.IOException;
import java.io.OutputStream;

public class SecretDataActions {

Klasa narzędziowa – tylko metody static (nie tworzymy jej obiektów).

    public static <T extends HaveFunctionPrintOnScreen> void printOnScreen(T data) {
        System.out.println("Wykonuję: <T extends HavaFunctionPrintOnScreen> void printOnScreen(T data)");
        data.printOnScreen();
    }

Przeciążenie 1. <T extends HaveFunctionPrintOnScreen> – ograniczenie górne: T musi implementować interfejs. Metoda wypisuje komunikat „Wykonuję: …” i woła data.printOnScreen() (metoda obiektu). Po wymazaniu typów (type erasure) sygnatura to printOnScreen(HaveFunctionPrintOnScreen).

    public static <T1, T2> void printOnScreen(SecretData<T1, T2> data){
        System.out.println("Wykonuję: <T1, T2> void printOnScreen(SecretData<T1, T2> data");
        System.out.println(data.getData1() + " " + data.getData2());
    }

Przeciążenie 2. Przyjmuje dowolny SecretData<T1,T2> i wypisuje oba pola jedną linią (data1 + " " + data2) – inny sposób wypisania niż w 1, żeby dało się odróżnić, które przeciążenie zadziałało. Po wymazaniu: printOnScreen(SecretData) – inna sygnatura, więc przeciążenia mogą współistnieć.

    public static <T1 extends Number, T2 extends Number> double sumOfData(SecretData<T1, T2>data){
        double sum = data.getData1().doubleValue() + data.getData2().doubleValue();
        return sum;
    }

sumOfData – oba parametry typu mają ograniczenie extends Number (Integer, Double, Long…). Dzięki temu wolno wywołać doubleValue() i zsumować różne typy liczbowe. Dla SecretData<String,…> wywołanie się nie skompiluje.

    public static <T2 extends OutputStream> boolean writeToStream(SecretData<String, T2> data){

        OutputStream outputStream = data.getData2();
        String text = data.getData1();

        try{
            outputStream.write(text.getBytes());
            outputStream.write('\n');
            return true;
        } catch (IOException e){
            return false;
        }

    }

}

writeToStream – pierwszy typ to dokładnie String, drugi dowolna podklasa OutputStream (np. PrintStream z System.out, FileOutputStream). Zapisuje bajty tekstu (getBytes()) i znak '\n'; IOException jest łapany i metoda zwraca false, sukces → true.

1.2 · MathOperation.java – interfejs funkcyjny

@FunctionalInterface – kompilator pilnuje, żeby była dokładnie jedna metoda abstrakcyjna. Taki interfejs można zaimplementować lambdą: (a, b) -> a + b. Metoda bierze dwa double i zwraca double.

1.2 · MathCalculator1.java i MathCalculator2.java 
package org.example;

public class MathCalculator1 {

    public static double executeOperation(double x, double y, MathOperation operation){

        return operation.performOperation(x, y);
    }
}

Wersja 1 – własny interfejs. executeOperation dostaje dwie liczby i operację, i zwraca operation.performOperation(x, y). To funkcja wyższego rzędu: kod (operacja) przekazany jak dane – wzorzec strategii.

package org.example;

import java.util.function.BiFunction;

public class MathCalculator2 {

    public static double executeOperation(
            double x,
            double y,
            BiFunction<Double, Double, Double> operation ){

        return operation.apply(x, y);
    }

}

Wersja 2 – standardowy BiFunction<Double, Double, Double> z java.util.function (dwa argumenty → wynik; metoda apply). W typach generycznych muszą być klasy opakowujące (Double, nie double); argumenty x, y są autoboxowane, a wynik rozpakowany do double.

package org.example.persistence;

import org.example.model.*;
import org.hibernate.Session;
import org.hibernate.SessionFactory;
import org.hibernate.cfg.Configuration;

public class HibernateSessionFactory {

    private static final SessionFactory sessionFactory;

    static {
        sessionFactory = new Configuration()
                .addAnnotatedClass(User.class)
                .addAnnotatedClass(Problem.class)
                .addAnnotatedClass(Idea.class)
                .buildSessionFactory();

        Runtime.getRuntime().addShutdownHook(new Thread(sessionFactory::close));
    }

    public static Session getNewSession() {
        return sessionFactory.openSession();
    }
}

Klasa statyczna. Blok static wykonuje się raz, przy pierwszym użyciu klasy: Configuration (czyta hibernate.properties) + zarejestrowane encje → buildSessionFactory() (kosztowne, więc raz na aplikację). Shutdown hook – osobny wątek uruchamiany przy kończeniu JVM zamyka SessionFactory i połączenie z bazą. getNewSession() zwraca świeżą Session (jednostkę pracy) w każdym miejscu użycia.
